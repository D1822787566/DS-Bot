# Bot 表情球与共享表情库

- 日期：2026-11-06。
- 状态：用户已确认产品方向、头像展示、短时情绪、表情使用范围、版本应用，以及集成现有 `ds-bot` 插件的接入方式；功能尚未实现。下文标为「实现建议」的技术细节仍需在实现时核对。
- 目标：每个 Bot 有可识别的动态形象，Chief DS Bot 可以通过对话设计新表情，用户可以在面板里查看、分类和分配表情。
- 相关：[产品愿景](../vision.md)、[UI 标准](../design/ui-standard.md)、[角色与权限](2026-10-07-roles-and-permissions.md)、[头像库](2026-10-23-avatar-library.md)、[Bot 视图](2026-10-20-widget-views.md)、[隐私 Bot](2026-10-27-private-bots.md)。

## 现有基础

- [characters.js](../../ds-bot/src/client/characters.js) 已有 Bot 颜色、轮廓和照片的解析；默认颜色按 Bot id 计算，当前实现不保证团队内颜色不同。
- [mark.js](../../ds-bot/src/client/mark.js) 的 `BotMark` 已支持动态形象、视线和 `idle / thinking / searching / working / sending / orbit / waiting / alert / done` 状态。上传照片没有可独立控制的眼睛等部件。
- [handoffs.js](../../ds-bot/src/host/handoffs.js) 和 [member-status.js](../../ds-bot/src/client/member-status.js) 已考虑同一 Bot 在私聊和多个群聊的工作情况。
- 现有头像库保存图片，按已定设计只允许用户修改；动态表情使用独立的数据和工具，不扩大图片库工具权限。

## 插件接入方式（已确认）

- 表情球能力集成到现有 `ds-bot` 插件，采用内部模块扩展；本功能不新增独立的 DSH 插件，也不为每个 Bot 单独安装插件。
- 每个 Bot 拥有自己的表情球实例，保存固定身份色、轮廓、动作风格和表情版本绑定；表情定义与渲染组件共享，运行中的工作状态与短时情绪按 Bot 和会话分别管理。
- 功能代码位于插件层，桌面应用沿用现有的插件承载方式；桌面端与 Web 端复用同一套表情定义、管理逻辑和界面组件。
- 内部按以下三个职责组织；模块是插件内部代码，具体文件名和工具名在实现时确定，不把职责划分误作新增安装包或已有 API。

| 内部模块 | 职责与接入位置 |
| --- | --- |
| 表情定义与校验 | 在 `ds-bot/src/shared/` 定义表情配置与校验契约，统一服务端校验、聊天预览和实际播放的含义 |
| 表情管理与 Agent 工具 | 在 `ds-bot/src/host/` 管理草稿、保存、版本、分配、权限和运行时表达请求；由现有插件入口安装，工具沿用 Bot Session 作用域 |
| 表情界面与动画 | 在 `ds-bot/src/client/` 扩展共享头像渲染、聊天预览和表情库面板；通过现有客户端构建流程生成 `client.js` |

- [代码证据] [现有插件入口](../../ds-bot/index.js)通过 `MODULES` 安装内部模块，并用 `teamTools` 向 Bot Session 提供工具；[对话工具卡](../../ds-bot/src/client/cells.js)由插件自己的客户端渲染。这些是接入基础，专用表情工具及预览卡尚未实现。
- 实现建议：以现有 `BotMark` 为统一头像扩展入口；专用表情预览优先扩展插件自己的工具卡，核对工具回执、草稿保存和历史回放流程，不预设必须向 `show_view` 的组件目录注册表情球。
- 接入遵守 DSH 公开插件 API；若实现中确有公开 API 缺口，记录缺口，不修改 DSH 或依赖其安装内部文件。当前设计没有已证实必须修改 DSH 的前提。
- 第一版采用内部模块，不额外拆分独立插件或发布独立渲染包；未来出现明确的第二个使用项目时，再评估提取共享代码库。

## 已确认的产品方向

### 每个 Bot 的身份

- 每个 Bot 有自己的固定基础色，用于识别身份；切换表情或工作状态时保留基础色。
- 每个 Bot 可以拥有自己的轮廓和动作风格；名称、角色标签与轮廓辅助识别，颜色不承担唯一识别职责。
- 表情定义在团队内共享，Bot 保存自己的选择或绑定，避免为每个 Bot 复制一整套表情库。
- 用户可以修改 Bot 的颜色。表情的局部高光、亮度和辅助效果叠加在基础色上，不把整个 Bot 换成另一种身份色。

- 表情球作为 Bot 的默认动态头像，出现在侧栏、聊天顶部和群成员列表；详情面板提供放大展示。
- 既有角色和照片头像保留为可选形象；已有 Bot 如何迁移，在实现前细化，不以确认默认形象为由批量覆盖已有设置。

实现建议：新 Bot 自动配色时优先选用团队内尚未使用的预设色，不自动重排已有 Bot 的颜色。预设色用尽或用户选了相近颜色时，继续使用名称和轮廓区分。

### 状态和情绪分别驱动

最终表现组合三部分：Bot 身份、真实工作状态、当前情绪表达。

| 部分 | 来源 | 作用 |
| --- | --- | --- |
| 身份 | Bot 设置 | 固定颜色、轮廓、名称 |
| 工作状态 | 系统运行事件 | 空闲、思考、搜索、执行、发送、等待、需要处理、完成等 |
| 情绪表达 | Bot 根据当前上下文从已分配的表情中选择，或用户手动预览 | 好奇、自信、担心、困惑、满意、受挫、庆祝等 |

- 系统决定真实工作状态。Bot 选择「自信」或「庆祝」不会把任务标成成功；回合结束也不自动等于整个任务完成。
- 「需要处理」和等待用户批准的提示保持可见，情绪表达不遮盖它们。可自动恢复的工具失败不必升级为用户提醒。
- 工作状态决定基础动作，情绪通过眼睛、身体姿态、动作幅度、节奏和局部效果补充表达。
- 动画发生部件冲突时，先保留需要用户处理的提示，再保留工作状态动作；情绪只使用余下的部件或降低幅度。
- Bot 的情绪是界面表达，不作为 Bot 具有主观感受的事实判断，也不替代任务结果或文字说明。

实现建议：先支持好奇、自信、担心、困惑、满意、受挫、庆祝及中性复位。情绪请求使用表情 id、强度和有上限的持续时间；模型只在表达发生变化时发出请求，不为动画逐帧调用模型。

### 生效范围与结束

- 第一版采用短时情绪表达，播放结束后恢复真实工作状态，不延续为持续到下一次变化的长期心情；Bot 的个性通过固定动作风格体现。

- 同一 Bot 在多个会话工作时，聊天中的表情反映当前会话；团队列表中的表情反映 Bot 的汇总工作状态，不由最后一个会话任意覆盖。
- 新的系统状态、用户提醒或会话切换到来时，旧动画可以被打断；旧动画结束回调不覆盖较新的状态。
- 情绪结束后恢复当时的真实工作状态。Bot 仍在工作时，情绪结束不会把 Bot 重置为空闲。
- 普通工具结束、停止、失败与任务成功分别处理；「庆祝」或「完成」表达只对应实际触发它的事件。

实现建议：情绪请求绑定 Bot 和会话，由主机解析调用身份，不接受模型冒充其他 Bot。团队列表如何聚合多个会话的短时情绪，在实现前细化；重启不恢复已结束的短时情绪。

## Chief DS Bot 的对话设计

1. 用户在 Chief DS Bot 私聊中描述想要的表情。
2. Chief DS Bot 组合渲染器支持的部件和动作，生成声明式表情配置。
3. 配置通过主机校验后，在聊天中显示可播放的草稿预览。
4. 用户继续用自然语言调整，Chief DS Bot 修改同一份草稿并再次预览。
5. 用户要求「保存」时写入共享表情库；用户要求「应用到某个 Bot」时修改相应绑定。一次明确指令可以同时保存和应用，不增加重复确认。
6. 保存后的表情在面板中出现，标明分类、标签和来源。

可复用的设计指令示例：

> 给研究 Bot 设计一个“发现线索”的表情。先眯眼思考，再睁大眼睛，身体轻轻弹一下，整体保持克制。保留研究 Bot 的基础色，先展示预览。

- 生成能力取决于已有部件和动作；新增嘴型、肢体或全新的变形方式时，先扩展并验证渲染器。
- 生成数据不包含可执行 JavaScript、任意 HTML 或可注入的 SVG 字符串，由 DS Bot 的固定组件解释播放。
- 参数校验包括动作类型、数值范围、持续时间、关键帧数量、配置大小和部件能力。无效配置返回具体字段错误，保留已有可用表情。
- 内置表情和用户表情都使用同一份渲染契约，避免预览成功而实际应用失败。

实现建议：通过 `ds-bot` 自己的对话工具卡展示专用预览，复用同一表情组件；实现前核对工具调用数据、草稿身份和历史回放是否完整。当前 `show_view` 的固定组件目录没有表情球组件，这一事实本身不构成预览接入的阻碍；若进一步验证发现 DSH 公开 API 缺口，再按仓库规则记录。

## 表情库与面板

每个表情有一个主分类和若干标签。来源、使用情况分别筛选，不与主分类混用。

| 主分类 | 示例 |
| --- | --- |
| 工作状态 | 思考、检索、执行、等待、受阻、完成 |
| 情绪表达 | 开心、好奇、困惑、担心、满意、自信 |
| 互动反应 | 打招呼、点头、摇头、感谢、庆祝 |
| 日常动作 | 呼吸、眨眼、张望、打盹 |

- 来源筛选：内置、自制。
- 使用筛选：按 Bot 查看已分配的表情；读取范围遵守 Bot 隐私规则。
- 标签示例：克制、轻快、强烈；同一表情可有多个标签。
- 缩略图展示名称和静态姿态，选中或悬停后播放预览；详情可完整播放、编辑草稿、另存为新表情、分配给 Bot。
- 表情是面板内的一个入口，遵守现有右侧面板协调规则，不同时挤入第二个独立右栏。

### 修改与应用版本

- 修改已保存的表情时先编辑草稿，保存后形成新版本；预览修改不立即影响正在使用这个表情的 Bot。
- 已有 Bot 保留绑定的旧版本。用户要求「应用」后，才把所选 Bot 切换到新版本，其他 Bot 的绑定保持原样。
- 一次明确指令可以保存新版本并应用给指定 Bot，不增加重复确认。
- 旧版本的保留和删除策略须保证已有绑定继续可用；具体存储和清理机制在实现前细化。

实现建议：表情至少保存稳定 id、名称、主分类、标签、来源和动画配置；Bot 分别保存形象设置与表情版本绑定。具体版本字段和存储布局在实现前确定，不把对话里的 JSON 示例当成现有 API。

## 权限与原创材料

- 表情库新增专用工具；现有图片头像库继续遵守原设计。
- 用户管理全部表情；Main Bot 负责设计、保存和跨 Bot 分配；普通 Bot 根据当前上下文自动选择自己已分配的表情。校验实际 Main Bot 角色，不把名字「Chief」当权限凭证。
- Main Bot 的跨 Bot 操作沿用隐私 Bot 边界，不读取或修改隐私 Bot 的绑定；用户仍可在界面中管理。其他 Bot 可读的共享表情条目不携带私聊原文或隐私 Bot 的运行状态。
- 图形、动画和代码采用原创材料。外部 Emotion Ball 作为功能讨论背景，其素材和实现不直接进入仓库；若以后考虑引入外部代码，先按仓库的 Apache 2.0 兼容与 NOTICE 规则核验。

## 动效、性能与可访问性

- 继承现有安静、正常、活泼三档设置；日常动作出现在库中，不代表默认持续播放。
- 安静档保留必要状态变化；正常档增加用户互动；持续的空闲动作仅在活泼档开启。
- 系统开启减少动态效果时停止动画，以静态表情和文字提示保留含义。
- 逐帧动作优先使用变换和透明度，形状、位置和尺寸变化遵守现有弹簧规范。
- 历史消息中的头像保持静止；库内不可见缩略图和隐藏页面不持续播放。多个可见 Bot 的性能需要真实界面验证。
- 深浅主题下保持可辨识的身份色和文字对比度；名称、分类、选中态与键盘操作不依赖动画或颜色才能理解。

## 第一版验收

- 表情球随现有 `ds-bot` 插件加载，三个内部模块职责清晰；接入不要求安装额外的 DSH 插件，不修改 DSH，桌面端和 Web 端复用同一实现。

- 默认动态头像在侧栏、聊天顶部和群成员列表中保持同一身份形象；详情面板可放大展示，既有头像设置有明确迁移规则。
- 两个 Bot 使用同一表情时保留各自身份色；重启后颜色与表情版本绑定仍在，已结束的短时情绪不重播。
- 普通 Bot 只能自动选择已分配的表情；越过分配范围的请求有明确处理。
- 编辑并保存表情新版本后，已有 Bot 仍使用旧版本；应用给一个 Bot 时，其他 Bot 的绑定保持不变。
- 思考、搜索、执行、等待与用户提醒由真实事件触发；情绪结束回到当时状态。
- 任务失败或等待批准时，庆祝等情绪不遮盖提醒，不把任务显示为成功。
- Chief DS Bot 的描述、预览、连续修改、保存和分配形成可重复的完整流程。
- 错误配置被原子拒绝，Bot 继续显示已有可用表情；缺失部件有明确处理。
- 表情库按四个主分类展示，标签、来源和 Bot 使用情况筛选互不混淆。
- 多会话、停止、切换会话和延迟动画回调不会串改其他会话的状态。
- 角色和隐私检查覆盖工具调用及面板读取；新增工具不能借保存表情修改图片库。
- 三档动画、减少动态效果、明暗主题和键盘操作符合 UI 标准。
- 实现时运行仓库要求的单元测试、生成文件检查和 lint；主机改动另跑 mock smoke，界面行为提供真实演示证据。
